# 战斗回合详述

本文说明当前代码中的真实战斗与模拟战斗回合顺序。它补充 `docs/game_manual/07_combat.md` 的设计说明，以当前实现为准。

## 两条战斗路径

当前有两条战斗路径：

- 真实战斗：玩家在 UI 中点击按钮，`main.gd` 调用 `PlaySession`，再由 `BattleService` 执行动作。
- 模拟战斗：`RunSimulator` 调用 `CombatEngine.run_battle()` 自动跑完整场战斗，用于教程保护、campaign baseline 和测试。

二者共享 `CombatRules`、`Combatant`、`StatusService`、`TriggerService`、`EnemyActionRules` 等规则层。新增规则必须优先进入共享层，避免模拟战斗与真实战斗分叉。

## 战斗开始

真实战斗由 `PlaySession._start_current_battle()` 初始化。主要步骤：

1. 生成遭遇。
2. 调用 `CombatRules.build_enemies()` 构建敌人。
3. 重置玩家格挡、闪避、回合计数、充能状态、战斗日志、状态卡等字段。
4. 收集场地技能来源：`CombatRules.collect_scene_skill_sources(enemies + allies)`。
5. 应用套装战斗开始效果：`SetEffectService.apply_battle_start()`。
6. 触发玩家、敌人和盟友的 `on_battle_start`。
7. 如果敌人拥有先制效果，立即执行一次敌方攻击。
8. 进入玩家回合。

模拟战斗在 `CombatEngine.run_battle()` 内执行等价初始化。模拟器通过 `RunSimulator.set_seed()` 固定随机种子，保证测试稳定。

## 玩家回合开始

真实战斗进入玩家回合时，`PlaySession._start_player_turn()` 负责：

1. 回合数增加。
2. 清空玩家当前格挡。
3. 重置本回合行动标志。
4. 结算腐败：`CombatRules.resolve_corruption(player)`。
5. 随机充能：`ChargeService.random_ready_charge()`。
6. 触发玩家 `on_turn_start`。
7. 触发敌人和 AI 盟友 `on_turn_start`。
8. 抽取或推进状态卡。
9. 刷新界面消息。

模拟战斗在每轮循环开头执行等价逻辑，包括腐败、充能、玩家 `on_turn_start` 和玩家自动行动。

## 玩家基础行动

真实战斗玩家有三种基础行动：

- `player_attack(target_index)`
- `player_defend()`
- `player_dodge()`

它们都在 `BattleService` 内检查 `session._can_act()`，然后调用 `execute_skill()` 执行对应 innate skill。

### 普通攻击

真实战斗普通攻击顺序：

1. UI 传入目标 index。
2. `PlaySession.player_attack()` 委托 `BattleService.player_attack()`。
3. `BattleService` 用 `session._valid_target()` 修正目标，处理嘲讽、隐藏、后排保护。
4. 使用 `session.player["innate_skills"]["attack_1"]` 获取普通攻击技能。
5. 调用 `execute_skill()`。
6. `ActionContext` 和 `ActionPipeline` 计算最终伤害。
7. `session.deal_damage()` 应用伤害。
8. 命中后触发 `on_hit_dealt`、`on_hit_received`。
9. 如果击杀，触发 `on_kill`。
10. 增加能量。
11. 消耗状态卡。
12. 调用 `_after_player_action()` 进入敌方阶段或结算。

### 防御

防御使用 innate defend：

1. 计算格挡值，优先使用 `block_power`。
2. 经过 `StatusService` 和 `ModifierPipeline` 修正。
3. 叠加到 `player_block`。
4. 增加防御行动能量。
5. 消耗状态卡。
6. 进入敌方阶段。

### 躲避

躲避使用 innate dodge：

1. 增加 `dodge_layers`。
2. 如果状态卡或技能要求，可能额外获得格挡。
3. 增加躲避行动能量。
4. 消耗状态卡。
5. 进入敌方阶段。

## 玩家技能

玩家主动技能由 `BattleService.use_skill()` 处理：

1. 检查战斗阶段。
2. 检查技能槽是否存在。
3. 检查能量。
4. 检查冷却。
5. 治疗技能检查目标是否合法。
6. 调用 `execute_skill()`。
7. 扣除能量。
8. 写入冷却。
9. 标记已行动。
10. 消耗状态卡。
11. 进入后续阶段。

当前技能分两种实现：

- 新版 `actions` 技能：交给 `SkillActionService` 和 `_execute_action_skill()`。
- 兼容旧字段技能：按 `type` 分支处理 attack、defense、dodge、heal、buff、debuff、duel、deflect 等。

新增技能优先使用 `actions`，不要继续扩大战斗流程里的旧字段分支。

## 伤害结算

真实战斗伤害主要经过：

1. `ActionContext` 描述行动来源、目标、技能、伤害类型和基础数值。
2. `ActionPipeline.compute()` 计算最终伤害。
3. `BattleService.deal_damage_to_target()` 处理易伤、抗性、护卫减伤。
4. `Combatant.apply_damage()` 处理闪避、格挡、护甲和 HP。
5. 暗影护甲反伤：`_apply_shadow_armor_reflect()`。
6. 裂变检查：`CombatRules.check_split_after_damage()`。
7. 触发器：命中、受击、击杀、闪避等。

模拟战斗使用 `CombatEngine` 内的对应方法，但逐步下沉到相同共享规则。

## 敌方阶段

玩家行动后，真实战斗进入敌方阶段。主要顺序：

1. 清空敌人和盟友本回合格挡/嘲讽。
2. 敌人技能冷却递减：`CombatRules.tick_enemy_cooldowns()`。
3. 每个存活敌人触发 `on_turn_start`。
4. 跳过死亡、尚未可行动或被打断的敌人。
5. `EnemyActionRules.choose_skill()` 选择敌人技能。
6. `BattleService.execute_enemy_action()` 执行技能。
7. AI 盟友按类似敌人流程行动。
8. 存活敌人和 AI 盟友触发 `on_turn_end`。
9. 结算回合末特性和场地效果。
10. 检查玩家死亡或敌人全灭。
11. 回到玩家回合。

敌人技能包括普通攻击、主动攻击、防御、姿态、闪避、嘲讽、召唤、治疗、buff、debuff 等。

## 敌人普通攻击

敌人普通攻击顺序：

1. 计算攻击段数：`CombatRules.enemy_attack_segments()`。
2. 每段对玩家应用伤害。
3. 闪避时触发玩家 `on_dodge`。
4. 命中时触发敌人 `on_hit_dealt` 和玩家 `on_hit_received`。
5. 命中后应用鼠类特性：`CombatRules.apply_rat_on_hit()`。
6. 命中后触发玩家反击和反伤。
7. 如果攻击者有 `swarm`，其他存活 `swarm` 友军各协攻一次；协攻不会再次触发群袭。

## 特殊规则

### 腐败

`corruption` 命中玩家时施加 `rat_corruption`。每个玩家回合开始结算一次，使用最后一次命中攻击力计算伤害，持续 3 回合。

### 尖牙减甲

`fang` 命中玩家时调用 `CombatRules.apply_armor_reduction()`，给玩家施加永久战斗内护甲降低 debuff。

### 裂变

`split` 单位受到伤害后，如果 HP 低于阈值且尚未触发，会分裂为两个半血单位。新单位设置 `available_round = 当前回合 + 1`，不会立刻行动。

### 召唤

召唤技能会追加鼠类 minion。新召唤单位同样设置可行动回合，避免当回合立即行动。

### 场地效果

`CombatRules.apply_arena_effects()` 处理：

- `toxic_mist`
- `shadow_domain`
- `blood_moon`

场地来源在战斗开始时收集，后续按存活单位检查。

### 套装效果

套装在战斗开始通过 `SetEffectService.apply_battle_start()` 应用。部分套装会添加 status trigger，后续由 `TriggerService` 执行。

## 胜利、失败和奖励

敌人全灭后：

1. `RunProgressService` 推进战斗或楼层。
2. 如果是教程，按固定流程解锁装备和技能。
3. 如果是正式战斗，生成奖励选项。
4. 奖励选择由 `RewardApplyService` 应用。
5. 单局状态可由 `RunStateSerializer` 保存。

玩家死亡后：

1. 阶段进入失败或结算。
2. active run 清空或停止推进。
3. 永久 profile 中保留允许继承的内容。

## 模拟战斗差异

模拟战斗由 `CombatEngine.run_battle()` 自动执行完整战斗：

- 玩家每回合自动普通攻击。
- 能量足够时自动使用第一个可用技能。
- 敌人行为使用同一套 `EnemyActionRules`。
- 奖励由 `SimulationRewardPolicy` 自动选择。
- `RunSimulator` 固定 seed，避免测试随机抖动。

模拟战斗用于验证数值曲线和教程/正式层可玩性，不直接驱动 UI。

## 抽象触发顺序

以下顺序用于理解新增 status、trigger、skill action 时应该挂在哪个阶段。实际实现仍以 `BattleService`、`CombatEngine` 和共享规则服务为准。

1. 进入战斗时加载双方单位、技能、被动特性和场地来源。
2. 先处理全场效果，再处理先发、开局格挡、开局状态等 `on_battle_start` 效果。
3. 回合开始时处理本方回合开始触发器、持续治疗、持续伤害、腐败、充能和状态卡。
4. 行动前处理攻击者、目标和全局的行动前修正。
5. 每段伤害依次处理闪避、伤害加减、伤害乘除、护甲减伤、格挡抵扣和 HP 扣减。
6. 命中后处理攻击者命中触发、目标受击触发、反击、反伤、裂变、破甲等效果。
7. 行动后处理攻击者、目标和全局的行动后触发器。
8. buff、debuff、治疗等非攻击动作走对应 action/status 管线，遵循同样的来源、目标和全局职责边界。

## 开发约束

- 新增目标选择、格挡、闪避、护甲、场地、特性和状态规则时，优先进入 `CombatRules`、`Combatant`、`StatusService` 或 `TriggerService`。
- 新增敌人行为决策时，进入 `EnemyActionRules`。
- 新增真实战斗流程时，进入 `BattleService`。
- 新增模拟专用自动策略时，进入 `CombatEngine` 或 `SimulationRewardPolicy`。
- 修改真实战斗后必须检查模拟战斗，反之亦然。
