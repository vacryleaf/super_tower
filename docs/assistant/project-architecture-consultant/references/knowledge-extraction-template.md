## 7. 项目适配点

| 通用接口 | Super Tower 适配 | 其他项目适配方式 |
| --- | --- | --- |
| 内容注册 | `DataCatalog` / `DataRepository` | 替换为目标项目的注册表或仓库 |
| 状态转换 | `Combatant` | 替换为目标项目的运行时实体转换器 |
| 行为决策 | `EnemyActionRules` | 替换为目标项目的决策模块 |
| 流程编排 | `PlaySession` / `BattleService` | 替换为目标项目的用例或流程服务 |
| 效果解释 | `ActionPipeline` / `StatusService` / `TriggerService` | 替换为目标项目的动作和事件系统 |
| 验收入口 | `run_tests.sh` / `run_tests.bat` | 替换为目标项目的跨平台测试入口 |

## 8. 反模式

- 把项目当前文件名当成通用架构概念。
- 把设计预留描述成已经可用的功能。
- 只给模块名称，不说明输入、输出和禁止职责。
- 在 UI、单个内容条目或测试脚本中复制核心业务规则。
- 为一个数据变化直接增加流程层分支，而不先检查已有 Schema 和解释器。

## 10. 验证方法

- 是否能在另一个项目中替换适配点后复用工作流？
- 是否能用一个真实需求生成一致的模块影响表？
- 是否能明确区分事实、假设和设计建议？
- 是否有自动测试、静态检查或人工验收步骤？
- 当项目文档与代码冲突时，是否能暴露冲突而不是静默选择？
