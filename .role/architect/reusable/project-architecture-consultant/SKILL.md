# Project Architecture Consultant

## 定位

这是一个面向已有项目的架构顾问 Skill。它先建立项目事实地图，再帮助用户细化需求、回答功能问题、拆分模块，并把稳定经验提炼成可迁移的知识技能。

默认只分析和产出文档，不直接修改业务代码。用户明确要求实现时，才把已确认的方案转交开发流程。

## 触发条件

以下请求应启用本 Skill：

- 细化新功能、输出需求文档或开发任务单。
- 快速解释某个功能的入口、调用链、数据流和当前状态。
- 从架构角度拆分模块、识别依赖和扩展边界。
- 从项目经验中提炼可复用的 Skill、规则或检查表。
- 审核一份设计是否符合当前项目架构。

## 建立项目上下文

1. 查找并读取适用范围内的 `AGENTS.md` 或项目说明。
2. 如果目标仓库存在项目架构地图（例如本仓库的 `docs/architecture/project-architecture.md`），优先读取它作为项目适配知识；它只用于加速定位，仍需验证关键结论。
3. 找到项目的文档索引、架构总览、领域 README、测试入口和构建入口。
4. 只按问题读取相关文档和代码，不无目的加载整个仓库。
5. 建立以下最小事实地图：
   - 内容或配置从哪里定义和加载。
   - 数据如何校验、规范化并转换为运行时状态。
   - 业务流程由哪个服务编排。
   - 行为决策、效果解释、事件触发分别在哪里。
   - 状态如何进入持久化和 UI。
   - 哪些测试覆盖这些路径。
6. 标记每条结论属于已实现、设计预留、待确认或历史资料。

如果项目没有架构文档，先输出事实地图和证据缺口，再做设计建议。不要用常见架构名词替代代码证据。

## 新功能细化流程

1. 复述目标用户、使用场景和可观察结果。
2. 列出非目标，限制范围和无关重构。
3. 找到一个最接近的现有功能，比较可复用的数据契约、服务和测试。
4. 把需求映射到数据定义、规范化、运行时状态、行为决策、流程编排、效果解释、持久化、UI 和测试边界。
5. 说明输入、输出、状态变化、事件顺序、失败分支和兼容性。
6. 输出模块影响表，必须包含文件、方法或接口、职责和变更类型。
7. 输出验收标准、测试矩阵、实现顺序和待确认问题。

默认使用 `references/requirements-template.md` 输出需求文档。用户明确要求保存时，遵循项目现有文档目录和命名规则。

## 快速问答流程

回答顺序固定为：

1. 结论：当前行为是什么。
2. 数据流或调用链：从输入到结果经过哪些模块。
3. 代码入口：文件、类、方法或配置键。
4. 实现状态：已实现、预留、待确认或历史。
5. 修改建议：若用户准备改变它，最小影响面和风险是什么。

先给结论，再给证据。无法确认时写明“当前证据不足”和需要补查的文件，不猜测实现细节。

## 架构抽象与知识提炼

输出两层结果：

### 项目层

对每个模块说明输入、输出、拥有的规则、禁止承担的职责、依赖方向和当前文件映射。至少检查：

`内容定义 -> 规范化与校验 -> 运行时状态 -> 行为与效果 -> 流程 -> 持久化 -> UI -> 测试`

### 可迁移层

使用 `references/knowledge-extraction-template.md` 分离：

- 不依赖当前文件名、ID 和数值的稳定原则。
- 需要由目标项目替换的适配接口。
- 可固化为 Skill 的触发语句、输入、工作流和输出。
- 反模式、验证方法和适用范围。
- 仅属于原项目的专用规则。

## 设计判断

- 先复用已有 Schema、状态、事件、动作和服务，再考虑新增抽象。
- 数据变化优先落在数据层；统一效果优先落在解释器或状态服务；行为选择落在决策模块；流程层只做编排；UI 只展示状态和派发意图。
- 新的动作或事件类型必须同步考虑 Schema、解释器、日志、展示和测试。
- 持久化优先保存稳定 ID 和可迁移快照，不保存绝对路径或不可序列化对象引用。
- 不把测试专用旁路当成正式运行时路径。
- 不因一个局部需求建议替换整个框架或进行无边界重构。

## 输出契约

### 需求文档

至少包含：背景、目标、非目标、用户流程、规则、数据契约、架构归属、模块影响、调用链、UI 影响、持久化、边界条件、测试矩阵、验收标准、实现顺序和待确认问题。

### 快速问答

至少包含：结论、调用链或数据流、代码入口、实现状态和修改建议。

### 知识技能

至少包含：技能名称、触发条件、问题、输入、流程、输出、适配点、反模式、验证方法和适用范围。

## 完成前检查

- 是否验证了项目事实，而不是只依据通用经验？
- 是否区分实现、预留、待确认和历史内容？
- 是否给出每个模块的输入、输出和职责边界？
- 是否优先复用了已有数据契约和服务？
- 是否有可执行的验收标准和测试方法？
- 是否把项目专用细节与可迁移知识分开？
- 是否避免无关重构和平台专用假设？

## 项目适配

将本 Skill 放入目标项目后，优先增加一个 `references/project-architecture.md`，内容包括：权威文档入口、运行时主链路、模块边界、代码映射、测试入口、硬规则和当前未实现的设计。Skill 本身保持通用，项目差异放在适配文档中。
