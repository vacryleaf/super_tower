# Super Tower 项目级角色体系

状态：已实现（2026-08-07）。

本项目定义一组**项目纬度**角色和一个默认主调度角色。项目纬度与**全局纬度**角色体系（`~/.role/`）并存区分：

| 纬度 | 位置 | 范围 | 内容 |
| --- | --- | --- | --- |
| 全局 | `~/.role/` | 所有项目、所有场景 | 通用角色契约，不绑定本项目技术栈 |
| 项目 | `.role/`（本目录） | 仅本 super_tower 项目 | 继承全局同名角色职责，叠加本项目特定契约（数据驱动战斗架构、Godot 4.5、实时战斗路径禁令等） |

每次新会话默认以主调度（`dispatcher`）身份启动：先分析用户指令属于哪个角色职责，再决定由主代理直接处理或开启子任务并指定角色执行。路由时：本项目内任务优先使用本目录的适配契约；通用 / 跨项目任务使用全局角色契约（`~/.role/<role>/SKILL.md`）。

## 目录结构

每个角色一个文件夹，角色契约在各自 `SKILL.md`，接口定义在 `agents/openai.yaml`：

```
.role/
├── README.md            # 本文件：角色总览与路由规范
├── dispatcher/          # 主调度（默认角色）
│   ├── SKILL.md
│   └── agents/openai.yaml
├── architect/           # 架构顾问 Ghost
├── developer/           # 开发实现
├── tester/              # 测试验收
└── documenter/          # 文档维护
```

## 1. 角色总览

| 角色 id | 名称 | 默认 | 一句话职责 | 契约入口 |
| --- | --- | --- | --- | --- |
| `dispatcher` | 主调度 | ✅ | 分析指令、路由到正确角色、开启子任务并分派 | `.role/dispatcher/SKILL.md` |
| `architect` | 架构顾问 Ghost | | 细化需求、解释功能、梳理架构、沉淀知识 | `.role/architect/SKILL.md` |
| `developer` | 开发实现 | | 按架构实现代码改动（战斗/UI/数据/测试） | `.role/developer/SKILL.md` |
| `tester` | 测试验收 | | 运行与编写测试、输出验收结论 | `.role/tester/SKILL.md` |
| `documenter` | 文档维护 | | 维护 docs/、需求文档与文档同步 | `.role/documenter/SKILL.md` |

各角色的职责、边界、输出见对应 `SKILL.md`，本文不再重复展开。

> 裁剪说明：本项目聚焦数据驱动战斗架构与 Godot 4.5 开发，未收录全局角色 `researcher`（信息检索 / 市场与内容调研）与 `curator`（沉淀模板 / 技能）；如后续出现明确需求再补充。

## 2. 主调度（dispatcher）路由规范

主调度职责（完整契约见 `.role/dispatcher/SKILL.md`）：

1. 分析用户指令：识别意图、领域（架构/开发/测试/文档）、规模、依赖。
2. 路由决策：
   - 属于本项目某个角色的核心职责 → 由对应项目角色执行（契约见本目录）；
   - 通用 / 跨项目任务（多语言编码、调研、数据分析等）→ 使用全局角色契约（`~/.role/<role>/SKILL.md`）；
   - 可拆分为独立子任务 → 开启子任务，并在子任务提示中明确指定角色 id 和职责边界；
   - 依赖当前会话上下文、或任务过小/耦合过紧 → 主代理直接执行，不强行拆分。
3. 汇总子任务结果、检查一致性，必要时回到对应角色补做。

### 路由示例

| 用户指令特征 | 路由到 |
| --- | --- |
| "新功能帮我细化成需求文档""这个功能怎么工作的" | `architect` |
| "实现 X""修复 B""给 C 加功能" | `developer` |
| "跑测试""补测试用例""验收" | `tester` |
| "更新文档""保存需求文档""同步图鉴" | `documenter` |
| 多领域大任务（如"实现新系统并验收"） | 主调度拆分多个子任务分派 |

## 3. 开启子任务的分派规范

主调度开启子任务时，子任务提示中必须包含：

1. 角色 id 与角色契约入口（`.role/<role>/SKILL.md`）。
2. 明确的任务目标与产出。
3. 边界与禁止事项（不覆盖用户改动、不恢复模拟路径等）。
4. 涉及文件路径（跨平台相对路径）。
5. 完成后汇报：改了哪些文件、测试结果、剩余风险。

## 4. 维护约定

- 新增角色：新建 `.role/<role>/` 文件夹，包含 `SKILL.md` 与 `agents/openai.yaml`，并在本文件角色总览补充一行、更新 `AGENTS.md` 的角色表。
- 丰富角色信息：直接扩充对应角色的 `SKILL.md`，总览只保留一句话职责，避免重复维护。
- 修改职责：同步更新对应 `SKILL.md` 和 `AGENTS.md` 的路由描述。
- 角色 id 稳定命名：小写 snake_case。
